MISSING GOODS RECEIPT — INVOICE EXCEPTION RESOLUTION
STANDARD OPERATING PROCEDURE (SOP)
Version 1.4

================================================================================
PURPOSE
================================================================================

This SOP defines how the agent resolves a MISSING GOODS RECEIPT exception, where
a supplier invoice has been received but no goods receipt (GR) has been posted
against the referenced purchase order (PO) in SAP S/4HANA. It applies after
three-way-match classification has identified the exception as a missing GR.

The key words "MUST", "MUST NOT", "REQUIRED", "SHALL", "SHALL NOT",
"SHOULD", "SHOULD NOT", "RECOMMENDED", "MAY", and "OPTIONAL" in this
document are to be interpreted as described in RFC 2119.

================================================================================
SCOPE
================================================================================

Process Type: missing_goods_receipt
SAP Modules:  MM (Materials Management), FI-AP (Accounts Payable)
SAP Service:  API_SUPPLIERINVOICE_PROCESS_SRV
Entities:     A_SupplierInvoice, A_PurchaseOrder, A_MaterialDocumentItem,
              A_PurchaseOrderScheduleLine

================================================================================
PRECONDITIONS
================================================================================

Before execution, the following MUST be true:

1. The SAP MCP Server is reachable for reads.
2. The case payload contains the supplier invoice number and fiscal year.
3. The agent MUST NOT treat an earlier run of this case as a source of fact.
   Conversation history from earlier runs of the same case MAY be restored (it
   is kept for 30 days), but tool results are not, so every value the agent
   compares or writes MUST be read from SAP in this run.

================================================================================
STEP 1: GATHER DATA
================================================================================

1.1  The agent MUST retrieve the invoice header and line items
     (A_SupplierInvoice), including the PO reference and expected delivery date.
1.2  The agent MUST query material documents (A_MaterialDocumentItem, filtered
     by PurchaseOrder/PurchaseOrderItem) for the PO line to confirm that no
     goods receipt exists. A_MaterialDocumentHeader carries no PurchaseOrder
     reference and cannot be filtered by PO line.
1.2a The agent MUST read the PO item's GoodsReceiptIsExpected
     (A_PurchaseOrderItem). IF it is true and STEP 1.2 found no goods receipt
     quantity, this is a missing goods receipt even when the item's
     InvoiceIsGoodsReceiptBased is false — that flag governs how invoice
     verification matches, not whether goods are expected. The agent MUST NOT
     conclude from InvoiceIsGoodsReceiptBased alone that no receipt is needed.

1.3  The agent MUST read the PO schedule line (A_PurchaseOrderScheduleLine) and
     record its ScheduleLineDeliveryDate. There is no delivery-tracking or ASN feed available
     to the agent, so the scheduled delivery date is the only in-transit signal.

================================================================================
STEP 2: DETERMINE GOODS-RECEIPT STATUS
================================================================================

2.1  The agent MUST classify the situation as exactly one of:
     - GOODS IN TRANSIT — the PO schedule line's ScheduleLineDeliveryDate is today or later.
     - NO RECEIPT, WITHIN WINDOW — the ScheduleLineDeliveryDate has passed, but the invoice
       is within {{MISSING_GR_ESCALATION_DAYS}} business days of receipt.
     - NO RECEIPT, OVERDUE — no GR after {{MISSING_GR_ESCALATION_DAYS}} business
       days.

================================================================================
STEP 3: APPLY RESOLUTION LOGIC
================================================================================

3.1  IF GOODS IN TRANSIT:
     - The agent has no timer and MUST NOT promise to revisit the case itself.
       It MUST raise a free-text ticket to {{CONTACT_WAREHOUSE}} stating the PO#, invoice#,
       the scheduled ScheduleLineDeliveryDate, and the date the invoice should be re-checked
       ({{GOODS_IN_TRANSIT_REMINDER_DAYS}} business days out).
     - The agent MUST update case state to "awaiting_human_input" with that
       re-check date and STOP.

3.2  IF NO RECEIPT, WITHIN WINDOW:
     - The agent MUST raise a free-text ticket to {{CONTACT_WAREHOUSE}} asking
       them to confirm received quantities and the expected receipt date. The
       ticket MUST include PO#, invoice#, vendor name, and the expected delivery
       date from the PO.
     - The agent MUST NOT ask this question by notification, because a
       notification cannot be answered and the case would never resume.
     - The agent MUST update case state to "awaiting_human_input" and STOP.
     - When the warehouse responds, the agent MUST use the confirmed quantities
       to continue resolution.

3.3  IF NO RECEIPT, OVERDUE:
     - The agent MUST escalate to {{CONTACT_PROCUREMENT}} with PO#, invoice#,
       vendor, and the number of business days overdue.
     - The agent MUST update case state to "manual_review_required" and STOP.

3.4  The agent MUST NOT post or release an invoice that has no corresponding
     goods receipt unless a human explicitly approves via one of the paths
     above.

================================================================================
STEP 4: CLOSE OR HAND OFF
================================================================================

4.1  Once a goods receipt is confirmed or posted, the agent MUST re-run
     three-way matching to resolve any residual quantity or price variance.
4.2  IF a write fails at any point, the agent MUST set the case to 'error',
     notify {{CONTACT_AP_TEAM}}, and STOP.
4.3  IF SAP refuses a Release after the goods receipt posts with "Invoice is
     not blocked and cannot be released therefore" (MRM_BASE/000), clauses 4.4
     and 4.4a of the invoice matching SOP govern instead of clause 4.2.

================================================================================
ESCALATION RULES
================================================================================

| Trigger                                   | Action                           |
|-------------------------------------------|----------------------------------|
| Goods in transit                          | Ticket to {{CONTACT_WAREHOUSE}}  |
| No receipt within window                  | Ticket to {{CONTACT_WAREHOUSE}}  |
| No receipt overdue                        | Escalate {{CONTACT_PROCUREMENT}} |
| SAP write failure                         | Notify {{CONTACT_AP_TEAM}}       |
