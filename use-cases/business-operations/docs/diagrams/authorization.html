Independent checks
  • A refusal comes back to the agent as a tool error, and the target is never called.
  • The SAP layer check and the run checks hold in every Cedar mode, so they are the gate while Cedar is off.
  • The run checks see only business-operations-* and sap-* calls. Every call to this use case's own tools needs a run grant; on sap-* they decide only for this use case's clients.
  • The agent's SAP reads need a live grant too, held to its packs' sap_system; the operator's reader reads without one. The invoker deletes a grant when its run ends.
  • Where a pack declares write_amount_field, the write's own amount is held to the case's amount and the limit.
  • With security.egress_request_action: block, the egress guardrail refuses a tools/call it would rewrite instead of masking it.
Tenant isolation
  • Off by default on the platform, and LOG_ONLY when first enabled: in both, Cedar refuses nothing. This use case's example config (platform.example.yaml) sets ENFORCE.
  • ENFORCE, which deployment.mode: production requires, keeps the reader client from writing and hides any tool no permit allows.
